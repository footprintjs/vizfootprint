# The Sheet and its Sources
## Decision document — vizfootprint's data-computation layer UI (2026-09-02, revision 2 under three verdicts)

### 1. Verdict

Yes, with one correction kept and two new ones. A two-tab, Excel-shaped surface is the right shape: **Sources** (declare where rows come from, see what each source vouched for, refresh it) and **Sheet** (the rows, with headers that carry type and stats), one Sheet tab per table so "two tabs" is the one-table case. Excel is the mental model every analyst arrives with, and the two strongest lineages split exactly this way — your own Weave Data Source Manager (source list on the left, Configure above Preview, "everything is a column") and the Power Query → sheet split in Excel and Power BI. What is Excel-like: a grid you scroll, a header row you sort and filter, a formula bar, a totals row, sheet tabs along the bottom, Ctrl+C, Ctrl+F. What is deliberately NOT Excel: the unit is the **column, never the cell**.

The correction kept: a derived column is a declared computation — data, not code — and every derivation, rename, type fix and hide is a commit with a cause. The two corrections the verifiers forced: (1) derived values do **not** land through `materializeColumn` — that door writes into the shared store in place and re-tallies the type, so two branches declaring the same field would read each other's numbers; derived values live in a **column overlay** addressed by declaring commit. (2) The grammar was too small for the first ten minutes of real use — it gains a keyed **lookup** (the design's own `cases_per_100k` could not be built without one), share-of-total, text and date arithmetic, and calendars as data. This is still not a spreadsheet — it is the data layer wearing a spreadsheet's clothes, with a storage path that keeps every branch honest.

### 2. Placement on the six-layer ladder

- **Layer 1 (data)** owns everything that is a record: `DataSourceDef`/`SourceDecl` (src/def, src/source), the derived-column grammar (`src/derive`), the view-query port (`src/query`), the column overlay store (in `src/data`, the memory provider's second table beside the base store), the data journal (`src/def/journal.ts` — new; the precedent is the ref-event journal in `src/branches/refs.ts`), and the Sheet's data port (`src/sheet`). The Workbook is the data layer's UI.
- **Layer 2 (smart)** feeds the headers: `profile(table)` — one `foldOnce` with `columnTypes`, `extent`, capped `distinct`/`groupCount`, a histogram with declared edges, and an absence tally, keyed by (table, version, visible overlay set) — is the ONE producer of header stats and the same profile the planned `recommendViews()` reads.
- **Layer 3 (chart)** reads declared columns by name; a derived column is an ordinary `ColumnFacet` whose `type` is computed from its tree, so the encoding picker offers it with no re-mapping.
- **Layer 4 (grammar)** reaches the sheet as a declared view with a voice (`point`, `match`, `interval`), grain `[]`, and edges in the link matrix like any chart.
- **Layer 5 (agent)** proposes columns through the proposal lane, asks `why()` of a column, and is shown names and types — never values (Q8).
- **Layer 6 (story)** gets a sheet beat whose reproducibility is stated precisely: the rectangle (rows, columns, sort, first visible row key), never pixels.

### 3. TAB 1 — Sources

**What it shows (one row per declared table, all from records that exist today):** the table name; `format · via · at` from `SourceDecl` (an inline payload never repeated); the engine (`memory | wasm | server`, the `engine: 'auto'` note quoted verbatim); the **row key** (`data[t].key`, or "positional — a refresh replaces, no delta, no addressable row"); the **grain** as stated or "not stated"; the **absence column and its vocabulary** (`AbsenceDecl.states`, `unknown` always present); the declared facets; **provenance** — `version`, `retrievedAt`, `rows` from `Overview.sources`; **capabilities** as badges each naming the refusal it would give; the **current refusal** as a banner naming the typed reason and the carrier's sentence; a **not opened** state for a declared source whose open was refused or not yet attempted (the Excel "connection only" lesson — a declaration is a fact before it is a load); **used by** — views bound to the table's columns, derived from encodings, live reencodes, link mappings, derived-column inputs and lookups, and prose bases (Tableau's "Sheets Affected", never maintained by hand); and `lintData()` results.

**What it does — Refresh.** Per table or all, `dashboard.refresh(tables)` renders a delta panel: unchanged | changed `{from, to, rows, delta}` | refused `{reason}`, plus `materialisedLost`. A refresh swaps one provider for the whole dashboard (`buildDashboard.ts:304`), so it is a dashboard-level act, never a branch-scoped commit; it lands in the **data journal** — `{table, from, to, retrievedAt, delta, requestedBy, at}` — dashboard-level facts only. Two things the code forced us to add: (a) the dashboard keeps a **listener set** and notifies every open session on refresh — today no session learns of one (session.ts reads `runtime.sources` only when stamping); (b) the journal is **persisted with the log export**, or a replayed session loses the cause of every version move. The tab says in words that **time travel across a refresh is labelled, not restored**: `dataMoved` is the honest label; the old rows are gone.

**What a re-derivation is, and where it is written.** Derived columns are branch-scoped commits, so "re-derive the declared columns" is a per-session, per-branch fact and cannot live in the dashboard journal. Each session keeps a small **re-derivation ledger** (system-caused entries `{address, table, from, to, at, outcome}`, not commits) that why() and the history strip read and the export carries. Staleness itself is never stored: it is derived at read as `derivedAgainst ≠ sources[table].version`, exactly as prose staleness is.

**The history strip per table:** the commit log's `data` family for that table interleaved with the journal's refreshes and the ledger's re-derivations, each with `requestedBy`, `intent` and time; clicking a commit is `seek`. Consecutive arrangement notes on one slot collapse at read (Vizier's rule) so a sort toggled three times reads as one line.

**The preview** is the real `<Sheet>` capped at `previewRows` (placeholder 1,000) and labelled "first N of 90,300 rows — a window, not the table". Counts and header stats stay full.

**The declaration editor — v1 scope:** every field renders from the def with "declared in the def" beside it. What a person may change lands as `column` commits (section 4). Changing `source`, `key`, `grain` or the absence **vocabulary** re-opens a table and is a dashboard act, read-only with a copyable declaration. **Adding a source moves forward to P5**, with this tab: "open my CSV" is every Excel user's first act, so the empty state must be the first screen — a drop zone with a closed list of accepted extensions and a typed `File Import Error` (Weave's Dropzone); a dropped CSV/JSON becomes `{format, via: 'inline', at: <text>}`, a URL `via: 'http'`, and only a node host writes `via: 'file'` — one door, `dashboard.addTable(name, decl)`, journaled.

**Joins: still OUT for v1 — but the reason changed.** The earlier claim that an aggregate over a group "covers most of what analysts reach for a join to do" was refuted by our own example: `cases_per_100k` needs population, the demo's `cells` table has no population column, and no group aggregate can fetch a value from another table. What analysts reach for first is not a fan-out join but VLOOKUP/XLOOKUP — Weave's key namespace, Airtable's lookup field. So v1 gains a **keyed lookup op** (section 4): one value from another table by that table's declared row key, refused at declaration when the key is not unique — no fan-out, no grain change, no ruling needed. True joins change row identity and grain (5–50× fan-out measured on the SAN port table) and are "declarations that change answers" — they keep their own decision page.

**The three lineages.** Your Weave (2014): the source list with per-row refresh/delete, Configure above Preview, the key column and key namespace as first-class with a not-unique warning (now a typed refusal), transforms that are themselves sources, and time-sliced column loading with a progress fraction — the `ColumnDataTask.iterate(stopTime)` shape is exactly the resumable fold this revision adds. Tableau's Data Source page: connections left, a capped preview that is also the editor, "Reset name" (every inferred fact keeps its source value beside it — our `null` = back to the declaration). Power Query: Applied Steps as a visible log without causes, positional by identifier so a rename breaks the load; ours are keyed by column and re-materialise from the log.

### 4. TAB 2 — Sheet

**The unit is the column.** A column is a reference `{table, field}` resolved against the current data version and the cursor's visible overlay set (Weave's `ReferencedColumn`), never a copied array. Grist, Airtable and Notion ship exactly this — one formula per column, read-only in the grid; Hermans's Duplicated-Formula smell cannot exist when a column is declared once, and Panko's per-cell error rate is the disease of the cell as unit.

**A derived column is a declared computation — the grammar.** A small closed **op tree**, never an expression string, a function, or a raw-SQL/JS escape hatch (JsonLogic's law; Tableau Catalog, dbt and Arquero all admit provenance dies at the escape hatch):

```ts
// src/derive/types.ts
type Expr =
  | { col: string }
  | { lit: number | string | boolean | null }
  | { op: OpName; args: Expr[]; calendar?: 'iso' | 'mmwr' }
  | { op: 'lookup'; args: [Expr]; from: { table: string; key: string; value: string } }
  | { param: string };                      // RESERVED, not built: a named literal the story and agent may vary
interface DerivedColumn {
  ops: number;                              // op-vocabulary version, so old declarations still render
  kind: 'row' | 'aggregate';                // 'window' planned, refused in v1
  expr: Expr;
  over?: { groupBy: string[]; where?: Expr }; // groupBy [] = the whole table; where = which rows the reducer runs over
}
```

**Ops v1**, one table (`src/derive/ops.ts`), every row carrying `arity`, a result-type rule, a **fold owner** (per-row step), a **SQL owner**, and — new — a **words owner** (the why-sentence fragment, so the sentence cannot drift from what ran): arithmetic `add sub mul div mod`; compare `eq ne lt lte gt gte between`; logic `and or not`; `if`, `case` (multi-arm), `coalesce`, `isAbsent`; number `round abs floor ceil rowMin rowMax`; string `concat lower upper trim length contains startsWith endsWith in split substring replace`; date on ISO strings `year month week dayOfWeek dateDiff dateAdd dateTrunc`; `cast(to number|string|date)`; `lookup`; and the reducers `count sum min max mean distinct` — one list shared with `ViewQuery.reduce`.

Three rules that were missing: **calendars are data** — `week` and `dayOfWeek` carry `calendar` (`iso` | `mmwr`, first day stated); the demo's own time axis is MMWR week (week 1 contains January 4, Sunday–Saturday), and an ISO `week` would silently disagree with the source's `week` column. **`today()`/`now()` are refused** — a column whose value depends on when it ran cannot be replayed. **`cast(to date)` yields an ISO string, never a `Date`** — CSV dates are strings, and a derived column's declared type is `date` by construction even though the bytes are strings (the overlay carries the computed type; nothing re-tallies it).

**Absence — one law, both owners.** A cell is **absent** when it is `null`, OR when the table's declared absence column says the row is not `present` (`AbsenceDecl`; in the demo a row whose `report_state` is `unavailable` carries `cases = 0`, and `cases / population` must be absent there, not `0`). Every op is **strict**: any absent input makes the result absent; division by zero is absent, never `Infinity`. The only ops that see absence are the three whose purpose is absence — `isAbsent`, `coalesce`, and `if`/`case` whose condition is absent (result absent). This deliberately departs from SQL's three-valued `and`/`or`, and the **SQL owner emits `CASE WHEN … IS NULL THEN NULL ELSE … END` wrappers** so DuckDB gives our answer, not SQL's. Per-op **semantics are pinned as a spec beside each row** — `round` half away from zero (DuckDB's half-to-even is wrapped), `mod` sign follows the dividend, division is always float, string compare is by code unit (no collation), `lower/upper` are Unicode default case mapping, non-ISO date text is absent — and the conformance fixture includes a negative modulus, a `.5` rounding, an integer division and a non-ISO date. Where an engine cannot match the pinned answer, the op is refused on that engine with `derive-unsupported-on-engine`, never approximated. Absence is **counted per column and per input** (`absentBy: {population: 1204}`) by the recorder, so the header's parenthetical is data.

**Kind, group context and basis.** `kind` is explicit (Malloy's dimension/measure split). What changed: a **row-kind tree may contain a reducer node when `over` is declared** — share-of-total and deviation-from-group-mean are the most common derived columns an Excel or Tableau user writes (`[cases] / SUM([cases])`, Tableau's LOD), and the earlier rule refused them. The reducer is evaluated over `over.groupBy` (`[]` = whole table) and broadcast by key; the SQL owner emits `x / SUM(x) OVER (PARTITION BY g)`. Reducers accept row-kind argument trees, so `SUMIF` is `sum(if(cond, x, null))` — absent, not zero, so the skipped count stays honest. **`over.where`** names which rows the reducer runs over: the demo's `cells` table holds state, region and total roll-ups as ordinary rows, so `sum(cases) over disease` double-counts unless the declaration says `where kind = 'state'`, and the why sentence prints it. **Basis: derived columns of both kinds run over the FULL table, never the live selection** — a per-selection aggregate is a measure (`ViewQuery.reduce`), not a column; the validator says so in words, the same distinction the session already draws for columns-channel analyses.

**Lookup.** `lookup(keyExpr) from {table, key, value}` reads ONE value from another table by that table's declared row key (or a named key column), matched on a `keyedIndex` built once per version. It is refused at declaration with `derive-lookup-not-unique` when the target key is not unique or absent (`keyedIndex.unkeyed > 0` or duplicates) — Weave's not-unique warning, now typed. Row identity and grain never change. SQL: a scalar subquery or `LEFT JOIN … USING(key)`. Lineage: an INDIRECT JOIN edge. `cases_per_100k = cases / lookup(jurisdiction from population.pop) × 100000` is the first live derivation, so the demo gains a small declared `population` table.

**Compile.** The tree's type is COMPUTED from the op table at declaration; its role defaults from kind and type; its **lineage record** is written at declaration (`src/derive/lineage.ts`, OpenLineage column-lineage shape) and is more than the tree's column refs: `inputFields` (DIRECT), `groupBy` (INDIRECT GROUP_BY), `where` (INDIRECT FILTER), conditions (INDIRECT CONDITIONAL), `lookupKeys` (INDIRECT JOIN), `basis: 'full-table'`, `declarationCommits` (the `type`/`parse`/`unit` slots a cast read), a materialised input's `basis: {kind: 'analysis', commitId}` (so why() does not stop at `cluster_id`'s name), and the dataset-level `derivedAgainst: {table, version}` that re-derivation updates. Derived-over-derived is a chain in dependency order; cycles are refused; chain depth is capped (`maxChainDepth`, placeholder 8).

**Execute — the overlay, not `materializeColumn`.** `materializeColumn` writes into the shared store in place, has no un-materialize, no collision guard, and ends with `store.columnTypes[name] = inferType(values)` — a derived column would be re-tallied (an all-absent column becomes `unknown`), two branches declaring the same field would collide physically, editing a formula would overwrite bytes an earlier commit vouched for, and `allRows` would leak branch A's values into branch B's rows. So the memory provider gains a **column overlay** beside the base store: values keyed by **address** `${field}@${declaringCommitId}`, each entry carrying `{type (computed), derivedAgainst, rowCount, absentCount, absentBy, kernelRun}`. `evaluate`, `columns` and every window take the cursor's **visible overlay set** from the session's fold and project rows explicitly — base columns plus visible overlays, nothing else. A field that exists in the base is refused (`derive-invalid: 'cases is a source column'`). Drop = the fold hides the address; the entry stays for time travel. A landing whose `derivedAgainst` no longer matches the store's version is a typed rejection `version-moved`, never a positional misalignment. Analyses keep `materializeColumn` today; moving `cluster_id` onto overlays is a later packet.

Per ruling 12 the memory engine's execution form is a footprintjs flowchart: one `derive` stage per column in dependency order, but the stage's **commit is a column HANDLE** `{address, version, rowCount, absentCount}` — values stay in the overlay; committing a 1M-value array per stage would structuredClone it (five columns = five 1M-element clones per refresh). `sliceForKey` slices by key, so handles preserve why(); progress is stage ends on the emit channel; rows bypass TypedScope's JSON round-trip under a pinned conformance test. The overlay keeps the **kernel run snapshot per address**, so after a re-derivation why() reaches the run that produced the values on screen and says "as re-derived at version Y". The fold itself becomes **resumable** — `foldSteps(rows, recorders, {from, until})` returning a cursor (Weave's `ColumnDataTask.iterate(stopTime)` — your own lineage) — because `foldOnce` is one synchronous loop and cannot yield to the scheduler's `Step(remainingMs)` contract or be cancelled. SQL engines: the ONE SQL owner emits `<expr> AS name`, `OVER (PARTITION BY …)` for group context, a `WITH` chain for derived-over-derived; the conformance test pins SQL text as a descriptor until DuckDB lands, then compares values.

**Refresh and derived columns.** A declaration can be re-run where an analysis output cannot — that distinction stands. What changed is **when and for whom**: re-derivation is **lazy, per branch, on the cursor's next read** of the column (only the cursor-visible set, normal tier, status line past the silent threshold), never eager across every branch into one store. Before it runs, the tree is **re-validated against the new column types** — an input whose TypeTally verdict moved is `derive-type-changed`, naming the version that changed it, not a stale badge. An input that vanished is `derive-input-missing`; the session prunes `allMaterialized`/`materializedByCommit` entries named in `materialisedLost` so the sentence never names a column the engine no longer lists. A refresh that arrives with a **source column whose name a derived column holds** is `derive-name-shadowed`: the source wins physically (it is the base), the derived column is marked and hidden until renamed. Between refresh and re-derivation the header reads "stale: derived against X, table now Y" (`derive-stale`), derived at read.

**Stamps that can be trusted.** Two silent misdatings were found: `stampData` stamps only the DEFAULT table's version (session.ts:518), so a column commit on `jurisdictions` or a derivation reading a second table was undated; and a formula edit changes derived VALUES without moving any table version, so `dataMoved` never fired for commits that filtered on the old values. Rule: every commit stamps `data` with **every table it touches** (its clauses, derivations, lookups and link mappings), and a sibling **`derived` stamp** lists the addresses of every derived column visible at the cursor — so `dataMoved` can say "formula of ratio changed" exactly as it says "table moved".

**Which verb — the ruling.** What must a person ask WHY about? The computation, the type, the role, the aliases a caption will quote — data. A rename needs a cause but no logic. Hiding and sorting need no WHY but must ride the log for a beat. Three homes:

1. **The `column` verb** — the eleventh semantic verb, ONE verb for the column object, shaped like `describe`. Record shape: `viewId = 'column:' + table`, `field` = the column name verbatim (a free string, never split), `value = {slot, value}`. The fold key is composed by ONE function `columnKey(table, field, slot)` in `src/branches/fold.ts` as `'column:' + JSON.stringify([table, field, slot])` — JSON-safe, so `report_state` or a dotted CSV header never collides — and nothing else parses it. `column:` joins `RESERVED_VIEW_PREFIXES` (which lives in `src/def/validate.ts`, not fold.ts) with the drift-pin test extended. **Slots** (each `null` = back to the declaration; last-wins; branch-scoped; undo/bringOver/compare arms): `formula` (derived columns only — on a source field refused; `null` restores a def-declared tree; **dropping is explicit `drop: true`**, since `null` cannot mean both), `label`, `type` (**source columns only**, the declared-type override `ColumnDecl.type` already is; on a derived column refused: "its type is computed: number — cast in the formula instead"), `role` (never `absence` — that is the def's), `scale`, `unit` (added to `ColumnDecl`, `ColumnFacet` and `whats_here` in the same packet), and the four the analyst lens named as the first ten minutes' acts: `format` (%, currency, decimals, date pattern — display only), `aliases` (a value → label map, refused on collision; a caption quotes the alias, so it must be declared), `parse` (options `cast` reads: date pattern, thousands separator, percent strings — without them a type fix mostly produces absences), `description`, plus `absence` (this column's tokens → the table's **declared** states, refused if it names a state outside the vocabulary — the vocabulary stays a dashboard act) and `order` (a declared category order for a discrete column, which axes and legends need). Why not `derive`, `analyze` or a `describe` namespace: unchanged from the first draft — one object, one verb, all slots replayable; `defineAnalysis` takes code and steps the FDR ledger; prose and computation must never share a fold key.
2. **Arrangement** = `navigate` on `layout:sheet:<viewId>`, family `design`, with the guard widened for that scope: `doLayoutNote` today accepts a plain string under `LAYOUT_VALUE_MAX = 500`, which a 30-column order exceeds. One prop = one fact, each a **validated JSON-safe value**: `sort` (a list of `{field, dir, absent}`), `hidden`, `order`, `frozen` (by column **names**, never a count), `firstRow` (the first visible row **key**, never an offset, so a beat reproduces the same first row across versions). `order` = declared order + unmentioned columns appended in def order, so a column added on another branch is never silently dropped. The layout commit is the record; the sheet's `ViewQuery.sort` is derived from it at read — never two sources. Layout notes are inert in `keyOf` and **do not branch** when issued from a past cursor (a note against the tip — the same reason they are inert; documented and tested), and `planUndo` may pop them. Widths and scroll position are per-viewer conveniences, never commits.
3. A **new commit family `data`** for `column:` commits (`familyOf` gains one arm), so the log's chips can hide or show column work.

**The formula bar** renders the tree as Tableau-style bracket text — `= [cases] / [population]` — with a kind badge, parses text back through a tiny grammar we own (`src/derive/formula.ts`, no eval), offers a **function palette** (description + example per op, from the op table) and **column-name autocomplete on `[`** (a non-developer cannot discover a closed vocabulary from an empty bar), and **previews the column in place beside its inputs before the commit lands** (Wrangler's in-place preview — its non-programmers "relied almost entirely on the previews").

**Why of a column.** `why({kind: 'column', table, field})` — `WhyTarget.column` gains `table` — anchors on the column commit and answers with **example rows first** (placeholder 5, inputs beside the result, one absent row), then the formula text, the generated words (nested trees as an indented step list — "1. population absent? → absent; 2. cases ÷ population" — never one clause chain), the absent count with `absentBy`, the lineage record, `derivedAgainst` and the refreshes since, and the kernel run. A **source column** has a why too: its `SourceDecl`, remote name, version, `retrievedAt`. A **cell** has "view source" (Gneiss): the raw record, its key or positional id, and its version.

**Column headers** carry: name (and source name when relabelled), type badge with the TypeTally verdict (`unknown` shows the tally), role, `=`/kind badges, a quality bar (present / each declared absence state / not-a-number), a distribution mini-bar, stale/refused/shadowed badges, sort and filter. All stats come from the **profile** — ONE fold per (table, version, visible overlay set), never the rendered window — with **two bases** side by side: "of 90,300" (whole table, cached) and "of 312 shown" (one fold over the current filter's indices, gesture tier — the bench measured 0.3–0.9 ms), because an analyst filtered to one state expects the totals row to be that state's. `distinct` and `groupCount` are **capped** (`distinctCap`, placeholder 10,000): exact up to the cap, then `{count: 'over', atLeast: cap}` shown as "more than 10,000 distinct" — the uncapped `distinct` holds every value in a Set and would blow memory silently at 1M unique ids. The mini-bar uses a `histogram(field, edges)` recorder with edges from the previous version's extent or the declared domain (the existing `equalWidthBins` is post-hoc over a values array — two passes); the first version pays one extra walk and says so. A `Sampled` badge is reserved for a scheduler-bounded walk or an engine whose fold is not ours.

**The grid is virtualized over the engine.** Every visible window is one `ViewQuery {table, filter[], columns, sort: [{field, dir, absent: 'first' | 'last'}], limit, offset}` answered as `{rows, count, version, start}`; every row carries a **`rowId`** — the declared key, or `${version}#${index}` for positional tables, **marked positional** so a select on it is a within-version act and a beat says so. `sort`, `offset` and `rowId` are what the sheet adds to the scheduler plan's spec (`EvaluateOptions` has `mode/columns/limit` only). The session adapter always projects to the fold's visible columns. **Sort is one cached permutation per (table, sort spec, version, addresses of derived columns in the sort)** — an `Int32Array`, built once — and a window walks the permutation applying the predicate (the same O(n) as today's `matchingIndices`); keying by filter would rebuild the sort on every brush. A small LRU per table, evicted on refresh. Scrolling is `navigate` that lands no commit; each window runs in the gesture tier under an epoch. **Find (Ctrl+F)** is a read: scroll-to-next-match in the gesture tier; "filter to matches" is the header filter, a commit.

**The parity oracle, stated precisely.** `selectedRows`' filter stays the port's first customer; `Overview.selectedRowCount` counts EVERY view's clause on the DEFAULT table with no self-exclusion and no link responses. So parity is asserted for exactly that configuration — the sheet on the default table, no own clause, every edge into it `filter` — at the same cursor. For the general case the session gains ONE function `clausesFor(viewId)` (own clause excluded, link responses applied) that both the sheet and a future per-view `selectedRowCount(viewId)` call, so the engine, not the UI, owns which clauses reach a view; a second fixture with one `highlight` edge asserts the sheet's count equals the fold of its incoming filter edges.

**Selections in the sheet are the charts' clauses.** A declared view (`ViewEncodingDecl` kind `sheet`, grain `[]`, voice `point | match | interval`): a row click emits a point on the row key (click-again clears; on a positional table a within-version point, marked), a header filter a `match` or `interval`, landing as `select`/`filter` commits. The default edge response into the sheet is `filter` (rows hidden, "312 of 90,300"), switchable to `highlight`; VizTable keeps dim-never-hide.

**Cell edits are refused with a next action.** "cases is a source column (version …); add a column, or annotate row 4021." On a **keyless table** the next action is itself refused with a sentence — there is no addressable row — and the tab's key field says why. Inline rows are not editable in v1.

**The agent proposes, a person accepts.** `column` with `proposal: true` rides the prose author port verbatim (`accept: <commitId>`, `decline: {proposal, reason}`, accepted derived never stored). The card shows formula text, the step list, the computed type, and `exampleRows` (placeholder 5) evaluated on a sample — **rows go to the person, never into the agent's context** (Q8). The validator bounds a proposal: chain depth capped, a proposal that reads a column not in `whats_here` refused, full evaluation only on accept.

**Copy and export carry their provenance.** Ctrl+C is a read: `cells(rect)` → TSV, capped (`copyCells`, placeholder 200,000 cells; above it `sheet-unsupported`), with a **header comment line** naming table, version, filter, sort and derived declarations — pasted numbers must not be undated the moment they leave. Absence states are written as their **words**, never blanks; dates as ISO. **Export CSV** of the filtered sheet (Weave had it) writes the same header as a sidecar with the journal.

### 5. Ports and adapters

- **Grid port `SheetData`** (core, React-free, `src/sheet/types.ts`): `capabilities {sort, filter: <clause kinds honoured>, countKnown, edit: false}` each false one naming its refusal; `columns()` → facets + profile; `count(question)`; `rows(question, window, {signal})` → `{rows, count, version, start}`; `cells(rect)` capped. **Two adapters ship in P4**: `sessionSheetData` (in-process) and `httpSheetData` (the demo reaches the session over `/api/state`, `/api/rows` polling — a per-scroll window is a network hop there), sharing one versioned block cache (`blockRows` placeholder 100, `maxBlocks` placeholder 50).
- **Provider door** (`src/data/types.ts`): `capabilities.canOverlay`; `putOverlay(table, {address, field, values, type, derivedAgainst})` → `ok | version-moved | derive-invalid`; `dropOverlay(address)`; `EvaluateOptions.overlays` = the visible addresses. `materializeColumn` stays for analyses.

### 7. Honesty

The sheet refuses or marks, never blanks or guesses. Gap kinds added to the D14 taxonomy: `derive-invalid`, `derive-input-missing`, `derive-source-refused`, `derive-type-changed`, `derive-lookup-not-unique`, `derive-unsupported-on-engine`, `derive-name-shadowed`, `derive-stale`, `version-moved`, `sheet-unsupported`. A type the rule cannot settle shows `unknown` with the tally and invites a declared `type` + `parse`; values that still do not fit become absent and are counted. `lintData()` gains the Hermans smells from declarations alone: chain depth over the cap, a column read by nothing, and a lookup whose target key is not declared. How a person asks WHY: the header's why, a cell's view-source, or `why()` — the answer is rows, steps, versions and the kernel run; never arrows.

### 9. Deliberately left out, and why

- **Per-cell formulas and edits** — the cell as unit is where duplicated formulas and Panko's error rates come from; row exceptions are `annotate` on a key (and refused, with a sentence, on keyless tables).
- **Pivot UI** — a pivot is a VIEW over `ViewQuery.groupBy + reduce`, not a second aggregation surface.
- **True joins** — the grain ruling and the "declaration that changes answers" law first; the keyed lookup covers the enrichment case without changing grain.
- **Spreadsheet formula import** — cell-addressed semantics have no faithful mapping to a declared column.
- **Window functions** — need a sorted walk and a frame vocabulary; the third `kind`, after the two engines agree.
- **Named parameters** — the `{param}` node is reserved so the grammar never breaks; the verb that changes one is undesigned.
- **Free-text SQL/JS columns, implicit measures, silent coercion, `today()`** — provenance, replay, or both die there.
- **Sampling by default** — a stat over a sample wears its badge; caps replace samples for cardinality.
- **Editing inline rows; lazy "connection only" opens; canvas rendering** — later dials, unbuilt.
